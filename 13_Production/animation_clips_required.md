# Humanoid animation clips required

The list to replace the A1 placeholder clips with real humanoid motion, either by Mixamo-style retargeting or by hand-authoring in Blender. Names match the Animator states in `Game/Assets/_Game/Art/Animation/Player.controller` (layer "Base" and layer "Combat").

## Rules for every clip
- Humanoid rig, 30 fps, T-pose or A-pose reference, facing +Z, feet at y = 0.
- **In place** unless the table says root motion. The `PlayerMotor` CharacterController moves the player; the Animator runs with `Apply Root Motion` off. Locomotion clips must have the stride speed that matches the blend tree: Walk 2.2 m/s, Run 6.5 m/s, Sprint 9.5 m/s (foot-slide is trimmed by the `SpeedMult` parameter, 0.6..1.6).
- Loop clips must loop cleanly (first and last pose equal, matching foot phase).
- Combat clips: the game scales playback so a phase clip fills the live phase window from `combat_tuning.json` (Startup / Active / Recovery of each hit), so author each phase clip as a complete pose-to-pose arc; absolute length does not matter, 0.3 to 1 s is fine. Damage timing is never taken from the clip.
- Add Animation events only where listed (`StartupEnd`, `ActiveBegin`, `ActiveEnd`, `RecoveryEnd` go to `CombatAnimationBridge.OnAnimEvent`; they are recorded, they never drive rules).

## Licensing
Nothing third-party was added in Wave A1. Every clip in the repo today is procedural (generated by `Editor/PlayerAnimationAssets.cs`). If clips are retargeted from Mixamo, check Adobe's current Mixamo terms first (royalty-free for use in games, but the animations may not be redistributed as standalone assets, and an Adobe account is needed, which only the user may create), then add each pack to `13_Production/third_party_assets.md` at the time it is imported. That file is not edited in A1. Hand-authored clips need no entry.
