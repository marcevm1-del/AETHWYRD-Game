## Bugs (ranked by severity)

### 1. High: a new game starts at 1 HP (1/162)
- **What you see:** every capture shows `HP 1/162`. The PlayMode test `ANewGameStartsAtFullHealth` gets `1/162` in the editor as well.
- **How to reproduce:** start the game with no save (or run any `-ascendShot`) and look at the HP bar.
- **Cause:**
  - `Game/Assets/_Game/Runtime/Combat/PlayerDefense.cs:42` sets `MaxHp = Hp = Mathf.Max(1, _combat.Stats.Hp)` in `Awake`, and assumes `PlayerCombat.Awake` has already run (the comment at `:41`). Unity does not guarantee the Awake order of components loaded from a scene. Here `PlayerDefense.Awake` runs first, and `Stats` is still the default `DerivedStats` struct (`Code/Ascend.Core/Player.cs:81`, so `Hp` = 0), which gives Hp = MaxHp = 1.
  - `PlayerCombat.Awake` then calls `RecomputeStats` (`PlayerCombat.cs:94`, which raises `StatsChanged` at `:67`). The handler at `PlayerDefense.cs:44` raises MaxHp to 162 but only clamps Hp (`Mathf.Min(Hp, MaxHp)`), so Hp stays at 1.
  - Hp is private-set, and this is the only code path that can produce exactly 1.
  - Returning players don't see it, because `PlayerSave.Load` calls `Revive()` (`PlayerSave.cs:133`).
- **Suggested owner:** gameplay-engineer.
- **Suggested fix:** make the order explicit. Either give `PlayerCombat` `[DefaultExecutionOrder]` ahead of `PlayerDefense`, or move the HP initialisation to `Start`, or refill HP when MaxHp is first initialised.

### 2. Medium: NPC name labels and place labels read mirrored from behind
- **What you see:** "Odo Hensley / Wheat farmer", "Guild Board", NPC roles and landmark names are mirrored when the camera is north of them (shots 02 and 10). The PlayMode test `NpcNameLabelsFaceTheCameraFromEverySide` finds all 12 NPC labels failing from 3 of 4 sides (36 failures). From the north the dot product is −1.00.
- **How to reproduce:** stand at (4,4), face south, and look at the plaza NPCs.
- **Cause:**
  - `Game/Assets/_Game/Editor/Ring0SceneBuilder.Npcs.cs:184-195` (`Label`) creates a static `TextMesh` that nothing turns at runtime. It is used for NPC names (`:176`), the Guild Board (`:44`), defence spots (`:166`), landmarks (`:213`) and the old well (`Ring0SceneBuilder.cs:201`).
  - The only rotation these labels ever get is baked by the editor preview renders (`Ring0SceneBuilder.cs:281-282`, `Ring0SceneBuilder.Whisperwood.cs:142-143`), which turn every TextMesh toward the preview camera before the scene is saved.
  - Only the `!/?` marker (`QuestGiver.cs:51`) and monster labels (`MonsterDummy.cs:248`) billboard each frame.
- **Suggested owner:** world-builder-engineer (add a billboard component to `Label()`). If the component lives in `Runtime/UI/`, ui-engineer writes it.

### 3. Medium-low: NPC names are drawn twice
- **What you see:** the HUD draws an on-screen nameplate (blue) and the world TextMesh label (white) for the same NPC, so the two overlap (shots 02, 06, 10).
- **Cause:** `RingZeroHud.cs:392-401` draws nameplates for QuestGivers. `RingZeroHud.cs:49` hides only monster world labels (`MonsterDummy.WorldLabels = false`) and never hides the NPC labels.
- **Suggested owner:** ui-engineer, with world-builder-engineer tagging the NPC labels so the HUD can hide them.

### 4. Low: HUD nameplates overlap the quest tracker
- **What you see:** an NPC nameplate is drawn over "Slime in the Well / Blue Slime 0/5" (shots 01, 02).
- **Cause:** `RingZeroHud.cs:141` draws `Nameplates()` before the HUD panels, and the overlap check at `:383`/`:396` compares nameplates only with each other, never with the tracker or minimap areas.
- **Suggested owner:** ui-engineer.

### 5. Low (test hygiene, **fixed** by qa-tester): `FieldScenePlayModeTests` loaded the player's real save
- **Problem:** the test loaded `Ring0_Graybox` with `PlayerSave.Folder == null`. In the editor that is the same `LocalLow/DefaultCompany/Game` folder, so `PlayerSave.Start` read the real `slot0.json`. That makes the test non-deterministic: the "you start inside the ward" check depended on where the saved character was. It could also write the slot on a waystone `PointSet`.
- **Fix:** the test now sandboxes `PlayerSave.Folder` in `[SetUp]` and restores it in teardown.

### 6. Low: the scene build churns `Ring0_Graybox.unity`
- **Problem:** every `BuildBatch` renumbers about 30k `fileID` lines with no content change, which buries real scene changes in review.
- **Suggested owner:** world-builder-engineer (deterministic object creation order or stable IDs).

### 7. Low: Farmer Odo stands inside the movement-test ramp
- **Problem:** NPC `npc_farmer_odo` at (6.5, 0, 3.5) (`Ring0SceneBuilder.Npcs.cs:19`) is inside the footprint of `Ramp` at (8, 1.1, 4), size 4×10 (`Ring0SceneBuilder.cs:141`). His capsule is cut by the slab (shots 01, 10).
- **Suggested owner:** world-builder-engineer.
