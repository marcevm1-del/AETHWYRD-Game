# 08b — Monster Motion Bible: Rigs, Physics & Movement

How every monster in Ascend is **built, rigged, moved and simulated**, written so Blender and Unity can follow it step by step. The design is deep (25 rigs, scaling laws, Menace/element/behavior motion languages, fair attack timing), but the pipeline is simple:

> **Build 25 rigs once → animate each rig once → every species is a mesh + a scale + generated numbers.**

| File | What it is |
|---|---|
| `Data/Monsters/rigs.json` | The 25 shared rigs: skeletons, IK and spring chains, hurtboxes, breakable parts, locomotion, physics, animation sets. Generated by `Tools/monster_gen/build_rigs.js` (edit there) |
| `Data/Monsters/motion_overrides.json` | Hand-authored motion design for the Ring 0–1 monsters (this doc §9) |
| `Data/Monsters/motion.json` | **Generated** per-species motion & physics profile for all species (`npm run motion`) |
| `Tools/blender/build_rig.py` | Builds any rig in Blender (with graybox proxies) and exports a Unity-ready FBX |
| `Code/Unity/` | Unity runtime components + the **Ascend → Build Monster Prefabs From Rig** editor tool |
| `Code/Ascend.Core/MonsterMotionLaws.cs` | The same scaling laws in plain C# for runtime (Named-monster growth, evolutions) |

## 1. Conventions (Blender ↔ Unity contract)
| Topic | Rule |
|---|---|
| Units | 1 Blender unit = **1 meter**. Scene unit scale 1.0. Frame rate **30 fps** |
| Axes in Blender | **Z up**, creature **faces −Y**, +X is the creature's **left** |
| Axes in Unity | Y up, creature faces **+Z** |
| Rig size | Each rig is built at its **refSize** (e.g. goblins 1.1 m). Species are scaled in Unity by `prefabScale = sizeMeters / refSize`, so one animation set serves every species on that rig |
| Bone names | From `rigs.json`, snake_case, sides `_L` / `_R` (`upperarm_L`, `ear_01_R`). **Never rename**: hurtboxes, springs, parts and hit bones are found by name |
| Special bones | `root` (on the ground, root motion) · `weapon_L/R` (hitbox & prop sockets) · `eye_*` (look-at) · `ik_*` and `pole_*` (Blender controls only) |
| FBX export | Forward **−Z**, Up **Y**, Apply Scalings **FBX Units Scale**, **Apply Transform off** (Blender's FBX exporter calls it "experimental … known to be broken with armatures/animations"), **no leaf bones**, primary bone axis **Y**, secondary **X**, **all bones** (not deform-only), bake animation — plus the **axis fix** of the free *Blender To Unity FBX Exporter* add-on (Angel "Edy" García, MIT), so the FBX's root objects are written with rotation 0 and scale 1 instead of the usual 90° X. `build_rig.py --export` does all of this (and leaves the scene unchanged). By hand: install that add-on (*Edit ▸ Preferences ▸ Add-ons ▸ Install from Disk*, the single `.py` file) and use *File ▸ Export ▸ Unity FBX (.fbx)* — version 1.3.1 (from a fork of the repository) exported `small_biped` from Blender 5.0.1 with the same result as `build_rig.py` |
| File names | `rig_<key>.fbx` for the model; animations as `rig_<key>@<clip>.fbx` (Unity's `@` convention), clip names from §4 |
| Unity import | Rig: **Humanoid** for `small/medium/large/giant_biped` and `golem` (Mixamo-retargetable; their arms hang down, so expect Unity's *Character not in T-Pose* message: press **Enforce T-Pose** in *Configure Avatar*), **Generic** for everything else with **Root node = `root`**. Keep **Optimize Game Objects off** (hurtboxes and springs live on bones). Animation compression: Optimal; keep root motion on attack/charge clips |
| Verified (2026-10-22) | All 25 rigs build and export with Blender 5.0.1. Read back with ufbx, every FBX has all its bones (including the `ik_`/`pole_` controls), `root` at the origin, rotation 0 and scale 1 on every root object, and the creature facing +Z with its left side at −X in Unity's axes. A test animation exported this way matches Blender's bone positions within 1.1 mm. The RigKit inspector maps all 15 required Humanoid bones on the five Humanoid rigs, with knees and elbows pre-bent the right way. The Unity scripts compile against Unity 6000.6.7f1's engine and editor assemblies with no warnings. **Not tested yet:** importing into Unity, the prefab builder and play mode |

## 2. The Scaling Laws
Every number in `motion.json` comes from these few laws, so a 0.4 m slime and a 14 m dragon feel like they belong to the same physical world. The JavaScript generator and `MonsterMotionLaws.cs` give identical results.

| Quantity | Law | Why |
|---|---|---|
| **Mass** | `shapeK × density × size³` | Real volume scaling: twice as tall = 8× heavier |
| **Gait speed** | `√(Froude × g × legLength) × fantasyMult × menace × element × behavior` | *Dynamic similarity*: animals of any size switch gait at the same Froude number (walk ≈ 0.25, run 1–3, gallop 3–5, hop/bound much higher for small hind-leggers) |
| **Animation play rate** | `√(refSize / size)` (0.4–1.6) | A bigger version of the same creature moves slower and looks heavier, automatically |
| **Turn rate** | `turnDegPerSecAt1m / √size` (60–900°/s) | Small things snap around, big things wheel |
| **Attack windup** | `base(kind) × √(size / 1.7 m) × rankFactor × menace × element × telegraphColor × power`, **never below the fairness floor** | Big = slower and heavier, higher rank = faster, but every attack stays readable |
| **Fairness floor** | windup ≥ max(0.25 s, parry window + 0.18 s, 0.45 s − 0.03 s per rank) · recovery ≥ max(0.18 s, 0.32 s − 0.015 s per rank) | No "unreactable" attacks at any rank; always a punish window |
| **Rank factor** | `1 − 0.035 × rankIndex` (F = 0 … EX = 9), min 0.6 | S-rank monsters are about 20% quicker than F-rank ones |
| **Poise** | rig poise (combat tuning) × √scale × (1 + 0.15 × rank) × 1.15 if unique | Bigger and higher-rank enemies take more hits to stagger |
| **Hit-stop multiplier** | `1 + log10(mass / 50) × 0.12` (0.85–1.4) | Hitting something huge *feels* heavier (combat pillar: Heavy) |
| **Footstep camera shake** | `(mass − 400) / 20000 × shakeMax` | Only big things shake the screen |
| **Vocal pitch** | `(1 / size)^0.3` (0.45–2.2) | Small = squeaky, large = rumbling, consistent across all sound sets |

**Attack timing bases** (seconds at human size, F rank):
| Kind | Windup | Active | Recovery | Lunge |
|---|---|---|---|---|
| melee | 0.45 | 0.12 | 0.50 | 0.8 m |
| heavy | 0.70 | 0.15 | 0.75 | 1.2 m |
| charge | 0.80 | 0.60 | 0.90 | run speed × active |
| leap | 0.60 | 0.30 | 0.70 | 2 × size |
| ranged / projectile | 0.55 | 0.10 | 0.45 | — |
| breath | 1.00 | 1.20 | 0.90 | — |
| aoe | 0.90 | 0.30 | 0.90 | — |
| grab | 0.60 | 0.25 | 0.80 | 0.5 m |
| magic | 0.70 | 0.20 | 0.60 | — |
Telegraph colour multipliers: blue ×1.0 · **red (unblockable) ×1.15** · gold (grab) ×1.1 · none ×0.85. A generic "melee" kind is refined by the attack's name (Heavy Swing → heavy, Charge → charge, Pounce → leap…).

Example outputs (from a test run): a 0.4 m Blue Slime weighs ~35 kg and hops at ~3.1 m/s; a 1 m Goblin runs at ~5.1 m/s; a 3.2 m C-rank Ogre's Heavy Swing winds up in 0.90 s; a 14 m S-rank dragon's tail sweep in 0.97 s and its fire breath in 2.3 s.

### 3.1 Rig details
Each rig in `rigs.json` defines:
- **bones**: head and tail positions, normalized to size 1.0.
- **ikChains**: legs and arms (two-bone IK with pole targets in Blender), plus procedural chains (spine paths, tentacles, insect legs) solved in Unity.
- **springChains**: secondary motion.
- **hurtboxes**: shape, size, damage multiplier and part.
- **breakableParts**.
- **blendShapes**: the shape keys the mesh must have.
- **procedural**: runtime layers (§6).
- **locomotion** and **physics** presets.
- **anims**: the full clip list, with frames and events.

**Animation event IDs** (Unity: add an event calling `AnimEvent(string)` on `MonsterMotion`):
`footstep_L`, `footstep_R`, `telegraph`, `hit_on`, `hit_off`, `cancel`, `vocal`, `vfx`, `land`, `ragdoll`.

**Attack choreography.** Every attack has three phases, matching `combat.md`:
1. **Windup.** This is the telegraph. The colour flash fires on the `telegraph` event (blue = parryable, red = unblockable, gold = grab). The monster keeps tracking you at `trackingWindupDegPerSec`.
2. **Active.** The hitbox is live between `hit_on` and `hit_off`. Tracking drops to `trackingActiveDegPerSec`, so the monster commits to its direction.
3. **Recovery.** This is your punish window. The `cancel` event marks where the AI may cancel into another action, but only at higher ranks.

`motion.json` gives each attack's windup, active and recovery time in seconds and in frames. Re-time the attack clips to match, or let the Animator speed them up or slow them down.

**Animator Controller template:**
- **Parameters:** Speed (float), SpeedNorm (float), Attack (trigger), AttackIndex (int), Hit (trigger), HitHeavy (trigger), Stagger (bool), Launched (bool), Dead (bool).
- **Layers:** Base (locomotion blend tree on SpeedNorm: idle → walk → run/gallop), an additive Hit layer, and an upper-body masked layer for bipeds (aiming and throwing while moving).

## 6. Procedural Layers (Unity implementation guide)
Use Unity's free, official **Animation Rigging** package (`com.unity.animation.rigging`) plus the small scripts in `Code/Unity/Runtime`.

| Procedural tag | How to build it in Unity |
|---|---|
| foot_ik_ground | Animation Rigging **Two Bone IK** per leg + a raycast per foot each frame; lower the pelvis by the lowest foot offset |
| look_at_target, neck_aim_ik | **Multi-Aim Constraint** on head (and neck chain for dragons/wyverns) toward the player, weight by Menace (3+ = 1.0) |
| spline_follow_head (serpents, nagas) | Record the head's path; place each spine bone along it at its rest distance (a "follow the leader" chain); add sideways sine undulation by speed |
| tripod_gait_ik / wave_gait_ik (insects, spiders) | Procedural legs: each foot has a home point; when it's > stride/2 away it steps (arc 0.3× leg length) — tripod groups 1L-2R-3L / 1R-2L-3R, spiders in waves back-to-front |
| fabrik_reach (tentacles, vines, horror limbs) | Animation Rigging **Chain IK Constraint** toward a target; idle with Perlin noise on the target |
| wall_walk_align_to_normal | Raycast down from the body; slerp the root's up vector to the surface normal; gravity follows the normal |
| sine_wave_spine_by_speed (fish) | Rotate each spine bone by `A·sin(ωt − k·i)`, amplitude growing toward the tail, ω proportional to speed |
| squash_stretch_from_velocity | `SquashStretch.cs` |
| spring chains (ears, tails, manes, feathers, lobes) | `SpringChain.cs` (values from motion.json). Tails use `followAnimation` so authored tail swishes still play |
| stop_motion_stepping | `SteppedAnimator.cs` |
| freeze while watched | `FreezeWhenObserved.cs` |
| hover_noise_bob (spirits) | Offset the model on a Perlin curve (8 cm, 0.3 Hz); NavMesh baseOffset = hover height |
| breathing / heavy_breathing | Additive breathing clip, or scale `chest` by 1.0–1.03 on a sine |
| footstep_camera_shake | On `footstep_*` events: Cinemachine Impulse with `physics.footstepShake` |
| hit_lean_additive / jiggle_on_hit | On hit: rotate spine/chest away from the hit by 8–15° for 0.15 s, plus `SpringChain.Impulse` |
| rigid_segments (golems, skeletons) | Each mesh piece parented to one bone with no skinning; on death or collapse, unparent them as Rigidbodies |

## 7. Physics, Hits & Death
- **Body collider and agent.** The NavMeshAgent moves the monster, and its Rigidbody stays **kinematic** during normal play. For knockback, launches and ragdolls, switch to a dynamic Rigidbody (or a ragdoll), then hand control back to the agent.
- **Knockback.** The impulse is `attack force × (1 − knockbackResist)`. Some rigs can't be launched at all (giants, dragons); others can only be launched while staggered (large bipeds, golems).
- **Hurtboxes.** Trigger colliders on bones (layer `Hurtbox`), each with a damage multiplier. Heads are usually ×1.4–1.6, cores, weak points and eyes ×1.8–3.0, armoured parts ×0.5–0.8.
- **Breakable parts.** Each part has its own HP (a percentage of the monster's HP), drops its own material and changes the moveset (`onBreak`). Examples: `grounded_cannot_fly`, `no_tail_sweep`, `disarm`, `limp_knockdown`. Appraisal tier 3 shows which parts can break.
- **Poise and stagger** follow `combat.md` §4.3. The poise value is per species in `motion.json`.
- **Death styles:**
  - `ragdoll`: full ragdoll.
  - `ragdoll_crumple`: ragdoll with a 6-frame last-gasp pose first.
  - `heavy_fall_dust`: a scripted fall with dust and camera shake.
  - `cinematic_collapse`: bosses.
  - `splat_dissolve`: slimes.
  - `crumble_into_rubble` / `shatter_pieces`: golems.
  - `dissolve_into_motes`: spirits.
  - `flip_legs_curl`: insects and spiders.
  - `limp_chain`: serpents.
  - `float_belly_up`: fish.
  - `wilt_collapse`: plants.
  - `scatter_and_fall`: swarms.
  - `collapse_and_melt`: horrors.

### Blue Slime (`mon_blue_slime`) · rig `blob` · design size ~0.4 m
A teardrop of glossy blue gel that bounces everywhere it goes. The first monster most players fight: cute, readable, and slightly sneaky (Engulf).

**Idle**
- Breathing wobble: core scales 1.00→1.04→1.00 over 90 f (blend shape 'puff' 0→0.15).
- Every 4–7 s a 'look around' hop in place: 0.15 m high, lands with squash 0.35 for 4 f then overshoots to stretch 0.1.
- Eyes blink 18×/min (Charming); highlight on the crown rotates slowly toward the sun.

**Movement**
- Hop gait: anticipation squash 0.4 (6 f) → launch stretch 0.5 (2 f) → airborne roundness (8 f) → land squash 0.5 (4 f) → settle wobble via lobe springs (8 f). One hop covers 0.6 m at refSize.
- Turns happen mid-air only (no ground pivot), so it 'faces' you between hops.
- On slopes it slides 0.2 m after landing (gel friction 0.3).

**Combat**
- Body Slam (blue): squash low 10 f (telegraph flash on frame 4) → leaps on a 1 m arc → lands on target with a splash ring. Hitbox = core sphere during the last 4 f of the arc and the landing frame.
- Engulf (gold grab): only if the player stands still within 1.2 m for 1.5 s. The slime spreads into a puddle (blend 'squash' 1.0 + scale XY 1.6) for 18 f, then rises around the player. Mash/dodge escapes; damage over time inside.
- Split (higher tiers only): on death above E rank it pinches in two (blend 'split_pinch'), spawning two mini slimes at 0.5× size with 20% HP.
- Tide Lash: a lobe stretches into a 1.2 m whip (lobe_front spring stiffness drops to 0.05 for the swing) and snaps back.

**Hit reactions**
- Light hit: squash toward the hit direction 0.3 + jiggle impulse on all lobes; slides back 0.3 m.
- Heavy hit: flattens like a pancake for 6 f, then pops back with a 'boing' (stretch 0.4 overshoot).
- Launched: becomes a perfect sphere, spins slowly; on landing it bounces once (restitution 0.4).

**Blender**
- Model one smooth dome (≈1,200 tris) with the inner Gel Core as a separate object parented to inner_item.
- Shape keys: squash (Z ×0.5, XY ×1.35, keep volume), stretch (Z ×1.5, XY ×0.82), puff, blink_L/R, smile, frown, split_pinch.
- Weight lobes with soft falloff (radius 0.35) so the springs read as jelly, not bones.

**Unity**
- Material: toon shader with refraction fake (matcap) + rim light; inner item visible through 30% transparency.
- Add SquashStretch (velocity → squash/stretch blend shapes) and SpringChain on the four lobes + crown.
- Collider: sphere; Rigidbody optional (NavMeshAgent drives it, hops are root motion).

**Death:** Pops: squash 1.0 for 3 f, then the mesh is replaced by a splash VFX + gel puddle decal that evaporates in 4 s. The Gel Core drops from the inner_item bone position.

**Attack overrides:** `atk_body_slam`: Leap arc 1 m; hitbox active on the descent only (hitbox `core`); `atk_engulf`: Only after the player is still for 1.5 s; gold telegraph is the puddle spreading (hitbox `core`); `atk_split`: Death/low-HP behaviour, not a normal attack (hitbox `core`); `atk_tide_lash`: Lobe whip, 1.2 m reach (hitbox `lobe_front`)

### Goblin (`mon_goblin`) · rig `small_biped` · design size ~1.0 m
Hunched, wiry, all elbows and grin. Fights in packs of 3–5: one attacks while the others feint, circle and throw junk. Cowardly alone, brave in groups.

**Idle**
- Shifts weight foot to foot every 2–3 s; scratches ear (ear springs flick).
- Looks at nearby goblins before acting (head look-at swaps between packmates and the player).
- Spins its crude blade in the hand (weapon bone rotates 360° over 20 f) as a fidget.

**Movement**
- Walk: knees bent 25°, spine hunched 20° forward, arms swing wide and low.
- Run: leans 35° forward; above 70% of run speed it drops to all fours (sprint_all_fours) for a burst.
- Circling: strafes at the pack's preferred range (≈3.5 m) with a bouncy side-step, blade pointed at you.
- Retreat: backpedals with tiny quick steps, then turns and runs when HP < 25% to call others (vocal 'call').

**Combat**
- Stab (blue, parryable): 12 f windup with the blade pulled back to the hip (telegraph frame 4), 4 f thrust with a 0.8 m lunge, 15 f recovery stumble (the punish window).

**Hit reactions**
- Light hit: head snaps back, ears flop (spring impulse), says 'ack!'.
- Heavy hit: spins 180° and lands on its backside, then scrambles up (getup 36 f).

- Proportions: head 30% of height, hands 1.4× human scale, feet long and flat. Ears are 2-bone spring chains.

## 10. Step-by-Step Workflows

### 10.1 Blender: from a design to an animated rig
1. **Build the rig:** `blender --background --python Tools/blender/build_rig.py -- --rig small_biped --proxies --export Art/Monsters/rig_small_biped.fbx`. Or run it in the Scripting tab with `ARGS_IN_EDITOR`. You get the armature, IK controls, bone collections (Deform, Controls, Springs, Sockets), spring settings as custom properties, and **graybox proxy meshes**, so it's animatable right away.
2. **Model** the creature over the skeleton at refSize, within the budget in §8. Keep separate rigid objects for weapons, horns, armour plates and other breakable parts.
3. **Skin it:** Ctrl+P → With Automatic Weights, then clean up. Use 4 weights per vertex at most. Rigid pieces (golems, skeletons, armour) get 100% weight to one bone.
4. **Add the shape keys** listed for the rig (e.g. squash and stretch on blobs, blink, snarl).
5. **Animate the core clip list (§4)** with the IK controls, one Action per clip, named exactly like the clip, at 30 fps. Put footstep, hit and telegraph frames where the event table says, or note your own frames for Unity.
6. **Export** with the same script (`--export`), or with the *Blender To Unity FBX Exporter* add-on (§1). Do not tick Blender's *Apply Transform*. Export animations as `rig_<key>@<clip>.fbx`, or all Actions in one file.
7. **Check** the skinned, animated rig with the RigKit skill (`.claude/skills/unity-3d-rigging-hitboxes`, `scripts/run_pipeline.py`): skin weights, Humanoid mapping, joint ranges, foot sliding/floating/knee pops in the walk cycles, hurtbox coverage.

### 10.2 Unity: from FBX to a fighting monster
1. **Add the scripts** as a local package, the same way Ascend.Core is added: put `"com.projectascend.monsters": "file:../../Code/Unity"` in `Game/Packages/manifest.json` (or copy `Code/Unity/Runtime` and `Code/Unity/Editor` into `Assets/_Game/Code/Monsters/`). The prefab builder reads `Data/Monsters/motion.json` straight from the repo, like `AscendData`; a copy at `Assets/_Game/Data/Monsters/motion.json` is only used when the repo's `Data` folder is not next to the Unity project.
2. **Install** Animation Rigging from the Package Manager (for the IK constraints; Cinemachine is already in the project). Add a `Hurtbox` layer.
3. **Import** `rig_<key>.fbx`. Set the rig to Humanoid (bipeds and golems) or Generic with Root node = `root`, and turn Optimize Game Objects off.
4. **Right-click the FBX → Ascend → Build Monster Prefabs From Rig.** Every species using that rig gets a prefab in `Assets/_Game/Prefabs/Monsters/`, already set up with:
   - its scale, NavMeshAgent, body collider and Rigidbody;
   - hurtboxes on bones, breakable parts and spring chains;
   - squash and stretch (blobs and Charming monsters);
   - stop-motion and freeze-while-watched (Dread and Horror monsters);
   - `MonsterMotion` holding the full profile.
5. **Assign** the shared Animator Controller template (§4) and add `AnimEvent(string)` animation events to the clips.
6. **Test** in the graybox field against the `combat.md` §12 fun checklist.
7. **Validate** the imported model with RigKit's Unity package (install: the skill's `SKILL.md`, step 7): *Tools ▸ RigKit ▸ Validator Window* checks the Avatar, skin, scale and facing, import options and samples the clips. Its collider checks cover RigKit's own hurtbox components, not `Ascend.Monsters.Hurtbox`.

### 10.3 Regenerating after data changes
| Command | Does |
|---|---|
| `npm run rigs` | Rebuild `rigs.json` from `build_rigs.js` |
| `npm run motion` | Rebuild `motion.json` for every species (add `-- --report` for the rig mapping table) |
| `npm run build` | Runs both as part of the full data build |
The generator prints a warning for any species it couldn't map to a rig. Fix it by adding the species' rigId as an alias in `build_rigs.js`, or by giving it a `rigKey` in `motion_overrides.json`.
