# Optional Online-Adjacent Features for an Offline RPG

## What do official sources explicitly claim about optional platform features?

### Takeaway
Steam documents several optional features that can complement an offline single-player game: Cloud synchronization, achievements/statistics, and screenshots. Steam Workshop enables community-created content, but its own documentation describes meaningful authoring, client-loading, validation, and moderation work. These are platform capabilities; their availability does not establish that a particular feature is right for Project Ascend.

### Cited Findings
- Steam Cloud stores selected game files remotely and makes saves available on another computer; the Steam client synchronizes them before and after sessions. Players can disable Cloud globally or per game. Auto-Cloud requires configuring file paths and quotas but does not require game code changes; the Cloud API offers more control. Steam warns that large or numerous files can consume bandwidth and delay shutdown/relaunch. [Steam Cloud](https://partner.steamgames.com/doc/features/cloud?l=schinese&language=english)
- Steam says screenshots are available through the Steam Overlay, with F12 as the default configurable hotkey; screenshots can be uploaded to a player's profile and the game's Community Hub. The Steam Screenshots API supports game-location metadata and other tags, and requires the Overlay to be active. [Steam Screenshots](https://partner.steamgames.com/doc/features/screenshots?language=english)
- Steam describes achievements as persistent, account-associated milestones shown on player profiles and community pages; stats can record more detailed values. Achievements require Steamworks API integration, are configured in Steamworks, can be hidden as spoilers, and names/descriptions can be localized. [Steam Stats and Achievements](https://partner.steamgames.com/doc/features/achievements?l=english&language=english)
- Steam's short achievement tutorial calls the basic integration under 10 lines and under 10 minutes, but explicitly requires the Steamworks SDK and a Steam client/user session for initialization and tests. That estimate is for a basic integration, not achievement design, art, localization, QA, or robust offline handling. [Step by Step: Achievements](https://partner.steamgames.com/doc/features/achievements/ach_guide?l=english&language=english)
- Steam offers two Workshop models: ready-to-use content without per-item curation, or curated items requiring developer approval and integration/update work. For ready-to-use support, Steam says developers need to consider client content loading, creation/editing tools, validation, file formats, style/content guidelines, and ISteamUGC integration. [Steam Workshop](https://partner.steamgames.com/doc/features/workshop?l=french&language=english)
- Steam's moderation guidance includes tools to hide incompatible or inappropriate content, ban violating items, and review reports; inappropriate previews can be blurred behind an age gate. The existence of these tools still entails moderator decisions and response time. [Community Moderation](https://partner.steamgames.com/doc/marketing/community_moderation?l=en)
- Larian's official Baldur's Gate 3 Patch 8 announcement describes a photo mode with camera/lens/scene settings, party positioning and expressions during exploration and combat, post-processing options during dialogue/cinematics, and local screenshot paths. It also says photo mode stickers may be extended by Toolkit mods. This is a shipped example, not a claim that the feature is inexpensive. [Larian: Patch 8 and Photo Mode](https://store.steampowered.com/news/posts/?appids=1086940&enddate=1754319570)
- Microsoft’s game accessibility guidance presents accessibility as design practice and lists examples including subtitles/captions, adjustable text size, remappable controls, color-independent cues, and difficulty options. Xbox Accessibility Guidelines are described as best practices, not legal compliance criteria. [Microsoft: Making games accessible](https://learn.microsoft.com/en-us/windows/uwp/gaming/accessibility-for-games); [Xbox Accessibility Guidelines](https://learn.microsoft.com/en-us/xbox/accessibility/guidelines)

### Inferences
- **Cloud saves:** Best optional convenience for a long RPG save, but the game should save locally and launch/play without Steam connectivity. For a small, well-bounded save format, Steam Auto-Cloud appears to be the lowest-effort route. Save versioning, interrupted sync, duplicate/conflicting saves, and backup/restore still merit deliberate design and testing; the source establishes synchronization behavior, not a conflict-free guarantee.
- **Achievements:** Suitable if they celebrate authored milestones and optional play styles. Use spoiler-hidden achievements for secrets, avoid achievements that require online access or dictate a single completion style, and treat platform unlocks as a mirror of local gameplay events. Steam-only achievements create platform dependence and need not be duplicated as an in-game progression system.
- **Photo sharing:** Start with Steam's default screenshot hotkey and local export/platform upload. An in-game camera is a separate product feature: camera collision/clipping, UI hiding, pose/expressions, image quality, and testing across scenes all create scope. A local photo mode/export preserves player choice and avoids building a hosted gallery.
- **Mods:** Do not promise a general Workshop at launch. If modding becomes a demonstrated community priority, begin with a narrow, data-only format and documented validation boundary; accept that even data-only content needs compatibility/version handling and content rules. Avoid executable scripts and arbitrary assets until the team can support security review, compatibility, and moderation.
- **Accessibility/social sharing:** Accessibility should be treated as core offline design quality, not as an online feature. Platform achievement/profile sharing can remain optional; public UGC or community submissions add moderation/privacy concerns and are not needed for social recognition.

### Gaps
- Official documentation does not quantify total development, support, privacy, moderation, or QA costs for a tiny Unity team. Scope assessments above are reasoned estimates, not vendor estimates.
- No official source reviewed here gives a complete, game-specific implementation recipe for a high-quality photo mode in Unity 6 or describes its full cost.
- Platform documentation changes over time; re-check Steamworks requirements and limits when Steam release planning is active.

## What player-facing principle follows, and which parts are inference?

### Takeaway
Ascend's settled product rules establish that play and progression must remain self-contained: premium, single-player, offline-first, with no online-gated rewards or real-world-time pressure. Optional services should add portability or expression while leaving the full game playable offline. The principle is grounded in canon; the feature ordering below is a recommendation inferred from canon and platform documentation.

### Cited Findings
- Canon defines Project Ascend as a premium, one-time-purchase, single-player PC game and lists offline-first economy rules: no player marketplace, real-money currency, loot boxes, daily timers, or online-gated rewards. It also rules out real-world-time deadlines, live-service world states, and online-gated consequences. [Project Ascend Canon](../../Canon.md)
- Canon says after a world-saving ending, players can continue in a peaceful open-ended world with optional exploration, hunting, bonds, building, slow-life activities, and regional recovery. [Project Ascend Canon](../../Canon.md)
- Canon includes proposed accessibility-conscious choices: multiple navigation guidance modes with accessibility equivalents, readable/redundant combat cues, adjustable assists, and viable non-parry defense. [Project Ascend Canon](../../Canon.md)
- Steam says platform features are optional and not all Steamworks features are appropriate for every product. [Steamworks Features](https://partner.steamgames.com/doc/features?l=english)
- Microsoft accessibility guidance recommends that essential information not rely on one channel alone and discusses alternatives such as captions, visual/audio cues, remappable controls, and adjustable text. [Microsoft: Making games accessible](https://learn.microsoft.com/en-us/windows/uwp/gaming/accessibility-for-games)

### Inferences
- **Recommended order for a tiny-team Unity Steam game:** (1) preserve local saves and add Steam Auto-Cloud after save format stabilizes; (2) add a modest, spoiler-aware achievement set after progression milestones are settled; (3) rely on Steam screenshots/local export first, then consider a deliberately bounded local photo mode if core world presentation supports it; (4) defer Workshop/mod support unless the architecture and team can support a narrow format and its lifecycle.
- Player-facing promise: online features are conveniences the player may disable or never use. Offline launch, core content, endings, saves, and progression do not depend on them. This is an inference that operationalizes the canon's offline-first rules.
- Privacy posture: keep saves on the player's device unless they opt into Steam Cloud; don't upload gameplay telemetry, photos, or save content to a developer-operated service. Platform screenshots and profile achievements are user-controlled Steam features, but profile/community visibility is governed by Steam settings and should be explained in plain language if linked in-game. These are recommendations, not claims that Steam's features have no privacy implications.
- Social-sharing principle: let players export and share artifacts they choose (screenshots, achievements) instead of creating live presence, chat, leaderboards, or community obligations. User-generated images can contain spoilers or inappropriate content if displayed in a shared hub; Steam moderation tools mitigate but do not eliminate that burden.
- An accessibility backlog is worth prioritizing ahead of online social features: captions/subtitle controls, remapping, readable UI, redundant cues, photosensitivity review, and forgiving input options help players in the offline experience and align with settled canon.

### Gaps
- Canon's offline-first economy and time rules are settled; the broader feature proposals in Canon are not automatically settled. The user should treat this note's platform feature ordering as research-informed recommendation, not newly approved canon.
- No user-supplied privacy policy or final release/platform scope exists yet. Steam is the present research comparison target because the request specifies a Steam game, but the canon says Steam planning is deferred until near the end.

## What scope risk does a tiny team face, and what should stay offline?

### Takeaway
The small-team risk is not simply API integration: every feature creates lifecycle work around failure states, support, compatibility, content, and player expectations. Keep world simulation, story branches, progression, endings, and the complete save loop local; use platform services only as optional mirrors or export destinations.

### Cited Findings
- Steam Cloud synchronizes matched files around sessions, and its documentation warns that large or numerous files can affect bandwidth and shutdown/relaunch; users can disable sync. [Steam Cloud](https://partner.steamgames.com/doc/features/cloud?l=schinese&language=english)
- Steam screenshots require the Overlay for the Steam Screenshots system; uploaded screenshots appear in the user's profile and game hub. [Steam Screenshots](https://partner.steamgames.com/doc/features/screenshots?language=english)
- Steam achievements depend on Steamworks initialization and an online/logged-on user context for the documented setup path. [Step by Step: Achievements](https://partner.steamgames.com/doc/features/achievements/ach_guide?l=english&language=english)
- Steam Workshop integration can require client loading, tools/editors, validation, file-format restrictions, guidelines, ISteamUGC, and in curated models developer review and game updates. [Steam Workshop](https://partner.steamgames.com/doc/features/workshop?l=french&language=english)
- Steam documents moderation workflows for inappropriate/incompatible screenshots and UGC, including hiding, blurring, bans, and reports. [Community Moderation](https://partner.steamgames.com/doc/marketing/community_moderation?l=en)
- Canon's scale is unusually demanding for a tiny team: it describes a 200–250 hour focused main story, 600–800 hours at explorer pace, a 1,000+ hour secret-ending route, ~2,500 named NPCs, 40 surface regions plus five Underworld layers and a 120-floor Great Labyrinth, and a long open-ended post-story. [Project Ascend Canon](../../Canon.md)

### Inferences
- **Keep offline:** save/load as the authoritative game state; combat and progression; quest and region consequences; unlocks and ending eligibility; post-game world state; accessibility settings; and any promised content. The Steam API being unavailable must never block any of these.
- **Good optional Steam layer:** Auto-Cloud only for compact save files, Steam achievements for local milestones, Steam Overlay screenshots, and user-initiated local screenshot export. These features map to existing player activity without requiring an online world simulation.
- **Privacy and moderation:** Avoid a developer-hosted account system, cloud backend, telemetry, public gallery, comments, or chat for this single-player scope. If using Steam Community UGC later, publish concise content rules and assign someone to review reports; the platform's moderation tools don't remove the team's responsibility to make decisions.
- **Platform dependence:** Steam Cloud and Steam achievements are Steam-specific. Encapsulate calls behind optional platform adapters and keep local save format/platform-neutral, so eventual non-Steam distribution does not need a rewrite of game logic. This is an architectural recommendation, not a Steam requirement.
- **Cloud-specific risk:** Establish save schema/versioning and backups before Cloud launch. Include a local-only option and a clear explanation that Steam sync is optional. Don't cloud machine-specific graphics/input settings with world saves. Test moving between devices and handling stale/duplicate copies before advertising cross-device continuity.
- **Mod-specific risk:** General mod support would expand into content schemas, version compatibility, malformed-file handling, crash reproduction, balance/story continuity, and potentially offensive or canon-conflicting submissions. A curated approach still means staff review and updates; an open approach moves more authoring burden into tools and client validation.
- **Photo-mode scope:** A basic screenshot button is nearly free because Steam Overlay provides it. A polished in-game photo mode is not: it competes with core camera, animation, UI and scene QA. The canon's no-fanservice rule makes clear style/content constraints particularly relevant if community photos or mods are surfaced by the game.

### Gaps
- No measured Unity-team hours or production budget were available; cost rankings are qualitative inferences from documented feature requirements.
- No decisions are settled here on Steam Deck support, cross-platform distribution, mod policy, cloud conflict UX, or a dedicated photo mode. Those choices depend on later release planning and capacity.
